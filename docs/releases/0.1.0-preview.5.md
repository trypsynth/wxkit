The fifth preview of WxKit translates an application, keeps it to one running copy, has it speak to screen readers through a live region, and adds the styled text control. Install it with `dotnet add package WxKit --prerelease`.

## What is new

Translations:

- `Translations` wraps wxTranslations, so an application's text and wxWidgets' own, such as stock button labels, follow one language. `Translations.Use` sets it up, and `Gettext` has gettext's shortcuts, `_`, `_n`, `_p`, and `_pn`, which work from any thread.
- The build compiles an application's catalogs with GNU gettext's `msgfmt`, and embeds them in it, with wxWidgets' catalogs for the same languages. `EmbeddedTranslationsLoader` finds them, so nothing ships beside the executable.
- `dotnet build -t:WxKitExtract` extracts the strings for translators, from C#, Visual Basic, and F#, and `dotnet build -t:WxKitUpdateCatalogs` merges them into each catalog. The build warns about a translation that loses or adds an accelerator or a shortcut.
- Catalogs can be laid out as an application likes, as `WxKitCatalog` items, and the template named by `WxKitTranslationTemplate`.
- Translations can be set up before `Application.Run`, so a command-line mode's text is translated too.
- `LanguageInfo` names a language in English and in itself, for a language picker, and `UILocale` has the user's preferred languages.
- `Application.LayoutDirection` sets the direction of windows with no parent, and of message boxes with no window under them, for an application whose language is a setting of its own, such as Hebrew on an English system.
- The settings sample is translated into German, and `docs/translating.md` describes it all.

Screen readers:

- `LiveRegion` has screen readers announce a message at a low, medium, or high priority, for news with no control of its own to land on, such as a status that changed. It is a UI Automation notification on Windows, a VoiceOver announcement on macOS, and an ATK notification on Linux.

One running copy:

- `SingleInstanceChecker` wraps wxSingleInstanceChecker. It needs no application, so `Main` can use it first.
- `SingleInstance.Claim` hands what a second copy was started with, such as files to open, to the first, which raises `MessageReceived` on its GUI thread. Only the same user can reach it: through a named pipe on Windows, and a Unix socket in a private folder elsewhere.

Other changes:

- `StyledTextCtrl`, Scintilla, with its events and constants. Only an application that uses it links it.
- `Image.LoadFile` and `Image.SaveFile` take a .NET stream, for an image in memory, such as one from Magick.NET.
- `MenuItem` has `Enabled`, `Checked`, and `Label`, and `Menu` has `AppendSubMenu`.
- The samples build from the newest WxKit package on nuget.org when there is no native build, so a fresh clone builds them without the build script.
- `UIActionSimulator`'s tests send input only while their own window is in front, so they can't type into another application.

## Platform differences

- `Application.LayoutDirection` does nothing on macOS, where Cocoa takes the direction from the languages the application is localized in.
- On Windows, which only lets the application in use bring a window to the front, a second copy lets the first bring its own forward.
- Without GNU gettext, the build still works, but warns, and the text stays in English.

## What is missing

- Dragging data other than files, and the optional grid and HTML libraries.
- Disk images and notarization as part of a publish. The docs give the commands, and Velopack does both.

The API will change before 1.0.

WxKit is heavily vibe coded. If AI-written code is a dealbreaker for you, this is not the project for you.
