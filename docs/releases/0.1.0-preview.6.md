The sixth preview of WxKit tells an application when it calls wxWidgets in a way wxWidgets doesn't support, adds an F# sample, and lists Scintilla and Lexilla in the third-party notices, which preview.5 left out. Install it with `dotnet add package WxKit --prerelease`.

## What is new

- The native libraries keep wxWidgets' assertions, the checks wxWidgets makes of how it is called, which it recommends keeping in release builds. A failed one raises `Application.AssertFailed`, with the file, line, function, condition, and message. Unless a handler marks it handled, it is written to `Trace`, and an attached debugger breaks. wxWidgets' own assertion dialog never shows.
- The HelloFSharp sample is the Hello sample in F#, which CI publishes with Native AOT and runs on every platform.
- `WxKitUpdateCatalogs` leaves a new string untranslated rather than guessing at its translation from a similar old one, which was wrong more often than not. Set `WxKitFuzzyMatching` to `true` to have it guess, as before.
- `WxKitExtract` and `WxKitUpdateCatalogs` keep each file's line endings, so a project that uses CRLF doesn't see every line change.
- The extractor leaves out an application's own wrappers of Gettext's shortcuts, such as `string _(string text) => Gettext._(text)`, rather than warning about each.
- The docs are about a third shorter, and match the code again. Open questions lists only what is undecided.

## Changes that may need code changes

- A call wxWidgets doesn't support, which went unnoticed before, now raises `Application.AssertFailed`, and breaks into an attached debugger. Fix the call, or set `Handled` for a failure you expect.
- Keeping the assertions adds about 0.9 MB to an executable. The Hello sample is 6.1 MB on Windows, from 5.2 MB.

## Licensing

- Scintilla and Lexilla, which the styled text control is built on, are in the third-party notices, and the native packages carry their license. They have been in the packages since preview.5, which didn't list them.

## Language support

- C# and F# are supported. Visual Basic should work, but isn't tested, and isn't supported with Native AOT, since it can't use the C#-only source generators Native AOT relies on.

## What is missing

- Dragging data other than files, and the optional web view, AUI, property grid, grid, and HTML libraries.
- Disk images and notarization as part of a publish. The docs give the commands, and Velopack does both.

The API will change before 1.0.

WxKit is heavily vibe coded. If AI-written code is a dealbreaker for you, this is not the project for you.
