The fourth preview of WxKit lets a control that draws itself describe itself to screen readers on Windows, macOS, and Linux, and adds printing. Install it with `dotnet add package WxKit --prerelease`.

## What is new

Accessibility:

- A window that draws itself can describe itself to screen readers on every platform. `SetAccessibleParts` gives it parts read as text, such as a status bar's fields. `SetAccessibleRows` shows it as a list or table, and `SetAccessibleCurrentRow` says which row to announce as the current one changes. On macOS and Linux they use what wxWidgets 3.3.4 added for its own list control and status bar, through NSAccessibility and ATK. On Windows, WxKit answers Microsoft Active Accessibility from them.
- A window described this way is named by the label just before it on Windows, as a standard control is, unless `SetAccessibleName` names it.
- A checklist sample, which draws itself, shows how.

Printing:

- `Printout`, derived from to draw each page and say how many there are, prints through `Printer`, or shows in `PrintPreview`.
- The print and page setup dialogs, and `PrintData`, `PrintDialogData`, and `PageSetupDialogData`, which they show.
- The text editor sample has Page Setup, Print Preview, and Print.

Other changes:

- Windows raise their mouse events, such as `LeftDown`, `LeftDoubleClick`, `MouseMoved`, and `MouseWheel`.
- A DC has its font, text measurement, such as `GetTextExtent` and `CharHeight`, and its coordinate mapping, which wxWidgets 3.3 moved to a base class WxKit did not bind.
- `Navigate` takes `NavigationFlags`, so a control that handles its own keys can move the focus backward for Shift+Tab.
- `UIActionSimulator` sends mouse and keyboard input as a user's is, for an application's own tests of its user interface.
- On Windows, the build script finds Visual Studio's own CMake when none is on `PATH`, thanks to André Polykanine. A project that needs the native libraries before they are built now says to run the build script.

## Changes that may need code changes

- `KeyEvent.KeyCode` is a `KeyCode`, generated from wxWidgets's key codes, rather than an `int`. A letter's or digit's code is its character, as in `(KeyCode)'A'`. Before, the key codes from the Menu key on were one off, since the generator read them from the interface headers rather than the real ones.
- `KeyEvent.Modifiers` and `MouseEvent.Modifiers` are `KeyModifiers`, rather than an `int`.
- The system colors are named with their words apart, such as `SystemColor.ButtonFace` rather than `Btnface`, and `SystemColor.HighlightText` rather than `Highlighttext`.
- `EventType.Listbox` and `EventType.ListboxDclick` are `EventType.ListBox` and `EventType.ListBoxDclick`.

## Platform differences

- On macOS, a window described by parts or rows needs `SetAccessibleName` for a name, since it does not take its label's.
- `UIActionSimulator` needs permission to control the computer on macOS.
- `Accessible`, which describes a control's parts with roles of their own, such as buttons, is still Microsoft Active Accessibility's, so on macOS and Linux it does nothing.

## What is missing

- Dragging data other than files, and the optional libraries, such as the styled text control, the grid, and HTML.
- Disk images and notarization as part of a publish. The docs give the commands, and Velopack does both.

The API will change before 1.0.

WxKit is heavily vibe coded. If AI-written code is a dealbreaker for you, this is not the project for you.
