WxKit 0.2.0-preview.1 is the first preview of 0.2.0, which changes the API where 0.1 got it wrong, so code written for 0.1 may need changes, which these notes list. This preview fixes the bugs a review of the whole API found. Later previews make the changes [Planned changes](../design/planned-changes.md) collects. Install it with `dotnet add package WxKit --prerelease`.

## Changes that need code changes

- Names that a control's own code couldn't use, since one of `Window`'s members hid them, are renamed:
  - The enum `AccessibleObject` is `AccessibleObjectId`, and the property `Window.AccessibleObject` is `Window.Accessible`. `Accessible.NotifyEvent` has an overload without the object, for the client area, where a control's parts are.
  - The enum `HitTest`, which `Window.HitTest` returns, is `HitTestResult`.
  - The event `Window.Char` is `CharTyped`, since it hid `System.Char`.
  - `ToolBar.Menu`, the same event as `ToolClicked`, is gone, since it hid the `Menu` class.
- `EventType`'s members whose words ran together are split, about 85 of them: `LeftDclick` is `LeftDoubleClick`, `ToolRclicked` is `ToolRightClicked`, `Mousewheel` is `MouseWheel`, `Togglebutton` is `ToggleButton`, `TextMaxlen` is `TextMaxLength`, and so on. Every `Webview` one begins `WebView`, every `Taskbar` one `TaskBar`, and every `Stc` one `StyledText`, as their classes do. `SetFocus`, `KillFocus`, and `SetCursor` are `GotFocus`, `LostFocus`, and `CursorRequested`, for what happened. The events themselves, such as `Window.LeftDoubleClick`, keep their names.
- Enum members whose words ran together are split, about 150 of them, such as `ListCtrlStyle.HorizontalRules`, which was `Hrules`, `FontWeight.ExtraBold`, `DatePickerCtrlStyle.AllowNone`, `ToolBarStyle.NoDivider`, `StockCursor.SizeNesw`, `SystemMetric.DoubleClickMsec`, and `FontEncoding`'s Mac encodings, such as `MacCentralEuropean`. The paper sizes named by inches are named as System.Drawing.Printing names them, so `PaperKind.One0x11` is `Standard10x11`. A style a control borrows loses the other control's prefix, so `ComboBoxStyle.TeProcessEnter` is `ProcessEnter`, and `ChoiceStyle.CbSort` is `Sort`.
- Members named after a type they aren't are renamed:
  - The enum `PaperSize` is `PaperKind`, as System.Drawing.Printing names it, and `PrintData.PaperId` and `PageSetupDialogData.PaperId` are `PaperKind`. `PageSetupDialogData.PaperSize` is a size.
  - `PrintData.Color`, a bool, is `IsColor`.
  - `NavigationKeyEvent.Direction` and `WizardEvent.Direction`, bools that say whether it's forward, are `IsForward`.
  - `StyledTextEvent.Alt`, `Control`, and `Shift` are `IsAltDown`, `IsControlDown`, and `IsShiftDown`, and its `DragFlags` is a `DragFlags` rather than an `int`.
- These events give a more specific class, since the class they gave couldn't say what they're for. A handler written as a lambda, or as a method that takes the class they gave before, goes on working:
  - `Window.ContextMenu`, and `EventType.ContextMenu`, give a `ContextMenuEvent`, which says where to show the menu, as when the keyboard opens it. They gave a `CommandEvent`, which doesn't.
  - `TreeCtrl.ItemContextMenu` is raised for an item, with a `TreeEvent` that says which, rather than for any context menu in the control.
  - `Window.SetCursor`, the event, and `EventType.SetCursor`, give a `SetCursorEvent`, whose `Cursor` a handler sets to give the window its cursor. They gave an `Event`, which couldn't.
- These are gone, since each could only do harm:
  - `GenericDirCtrl.Init()`, which left the control without its tree, so the next call into it crashed.
  - `ArtProvider.Pop()`, which, without a way to push a provider, removed one of wxWidgets' own, and the standard icons with it.
  - `Image.SetAlpha()` with no arguments, which gave the image an alpha channel of whatever was in memory. `InitAlpha()` gives it an opaque one.
  - `StyledTextCtrl.Hint`, which stopped the control's value from being set once it was, and `Margins`, `SetMaxLength`, `ForceUpper`, and the `AutoComplete` members, which do nothing there. The styled text control has them from wxWidgets' text entry, without what makes them work. Its own `SetMargins(left, right)` stays.
  - `Frame.DoGiveHelp`, `ToolBar.OnLeftClick` and `OnMouseEnter`, and `Window.ShouldInheritColors` and `InheritAttributes`, which wxWidgets calls on itself, and which did nothing useful called from outside.
  - `PropertySheetDialog.SetInnerSizer`, which kept a sizer nothing owned, so it could be freed while the dialog used it, and `AddBookCtrl` and `CreateBookCtrl`, which the dialog calls to make itself.
- Visual Basic isn't supported, and the translation extractor no longer reads `.vb` files.
- `WxKit.Interop`, the raw interface to the native library, is internal: `WxKitNative` and the `Wxk` types its functions take. Nothing public gave the native objects its functions need, so it could call little, and it changes whenever the native library does. If the API is missing something that sent you there, file an issue for it.

## Added

- An F# project that publishes with Native AOT compiles with `--reflectionfree`, so its records and unions don't give trim warnings. Set `WxKitReflectionFree` to `false` to compile without it.
- The samples are in `samples/csharp` and `samples/fsharp`, each in both languages, and there are four new ones: Library lists books in a data view with a model of its own, filtered as a search is typed, Checksums hashes files on another thread with a progress dialog that can cancel, Scrapbook uses the clipboard and drag and drop, and ProjectWizard is a wizard that skips a page that doesn't apply.
- The translation extractor marks a string passed first to `String.Format`, as F# formats a translation, as formatted, so that `msgfmt` checks its translations' placeholders.
- `StaticBoxSizer.StaticBox` isn't nullable, since the sizer always has its box.
- `SearchCtrl.TextChanged` is raised as the search control is typed in, for filtering as the user types. Its documentation lists only its search events, though every port sends it.

## Accessibility

- An `Accessible` that answers `AccessibleElement.Self` from `HitTest` or `Navigate` gives screen readers the window, rather than telling them nothing is there, which broke exploring the window with the mouse or by touch.
- `SetAccessibleParts`, `SetAccessibleRows`, and `SetAccessibleCurrentRow` work on Linux and macOS for a window with an `Accessible` of its own, which only Windows asks. They threw.
- A control after a `LiveRegion` is named by the label before the live region, on Linux and macOS, and a window with parts or rows is named the same way on Windows. The live region, whose text is announced rather than shown, was taken as the label. On Windows, Windows itself names a standard control by the text just before it, so put a live region somewhere other than between a label and its control.

## Members that couldn't work

- `ProgressDialog` has the members that show progress: `Update` and `Pulse`, which take a new message too, `Value`, `Range`, `Message`, and `Resume`, and `IsCanceled` and `IsSkipped`, which say whether the user canceled or skipped. It could only be shown.
- `Pen.Color` can be set, as `Brush.Color` can. wxWidgets' documentation gave its setter a parameter WxKit couldn't take.
- `ListCtrl.GetItemData` reads the data `SetItemData` gives an item, `FindItem` finds an item by it, and `ListItem.Data` and `ListEvent.Data` give it.
- `DataViewTreeCtrl` has `SetImages`, which gives the images its items' icons are indexes into. It had no images, so the icons were ignored.
- `Dialog.WindowModalClosed` says when a dialog shown with `ShowWindowModal` closes, and what it returned, since on macOS `ShowWindowModal` doesn't wait for it.
- Setters that wxWidgets clears with null take null: `Frame.StatusBar` and `ToolBar`, `TopLevelWindow.DefaultItem`, `SearchCtrl.Menu`, and `WizardPageSimple.SetNext` and `SetPrevious`. They threw.
- `WebViewFindFlags` is `[Flags]`, so its flags combine.

## Samples

- The Editor sample's printout kept the editor's font, which the editor disposed as soon as it made the printout, so previewing or printing ended the editor with an error. Its smoke test closed the preview before wxWidgets, which lays the pages out when it first draws one, used the printout, so CI didn't see it. The printout makes its own font now, and the smoke test waits for a page to be drawn.

## Leaks

- Replacing `Frame.MenuBar` destroys the menu bar it replaces, as the frame would have with itself. wxWidgets only detached it, so it stayed, with its menus and handlers.
- A `Printout` the application lets go of without disposing it is freed, as other native objects are. One given to a preview stays until the preview deletes it.
- Deleting an item from a `DataViewTreeModel<T>` forgets the items under it too, not only the item itself.

## Safety

- `Image.LoadFile(Stream)` loads nothing from a memory stream positioned past its end. It read past the stream's buffer.
- Freeing an object from the garbage collector's thread while the application exits can't reach the application as wxWidgets deletes it.
- Looking up a translation on another thread while the GUI thread adds a catalog, or sets the language, waits for it, rather than reading a catalog half added.
- `SingleInstance.MessageReceived` raises messages that arrived before `Application.Run`, when a handler was added before it. They waited until another copy sent one.

WxKit is heavily vibe coded. If AI-written code is a dealbreaker for you, this is not the project for you.
