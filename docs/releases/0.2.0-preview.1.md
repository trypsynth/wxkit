WxKit 0.2.0-preview.1 is the first preview of 0.2.0, which changes the API where 0.1 got it wrong, so code written for 0.1 may need changes, which these notes list. This preview fixes the bugs a review of the whole API found. Later previews make the changes [Planned changes](../design/planned-changes.md) collects. Install it with `dotnet add package WxKit --prerelease`.

## Changes that need code changes

- Names that a control's own code couldn't use, since one of `Window`'s members hid them, are renamed:
  - The enum `AccessibleObject` is `AccessibleObjectId`, and the property `Window.AccessibleObject` is `Window.Accessible`. `Accessible.NotifyEvent` has an overload without the object, for the client area, where a control's parts are.
  - The enum `HitTest`, which `Window.HitTest` returns, is `HitTestResult`.
  - The event `Window.Char` is `CharTyped`, since it hid `System.Char`.
  - `ToolBar.Menu`, the same event as `ToolClicked`, is gone, since it hid the `Menu` class.
- `EventType`'s members whose words ran together are split, about 85 of them: `LeftDclick` is `LeftDoubleClick`, `ToolRclicked` is `ToolRightClicked`, `Mousewheel` is `MouseWheel`, `Togglebutton` is `ToggleButton`, `TextMaxlen` is `TextMaxLength`, and so on. Every `Webview` one begins `WebView`, every `Taskbar` one `TaskBar`, and every `Stc` one `StyledText`, as their classes do. `SetFocus`, `KillFocus`, and `SetCursor` are `GotFocus`, `LostFocus`, and `CursorRequested`, for what happened. The events themselves, such as `Window.LeftDoubleClick`, keep their names.
- Enum members whose words ran together are split, about 150 of them, such as `ListCtrlStyle.HorizontalRules`, which was `Hrules`, `FontWeight.ExtraBold`, `DatePickerCtrlStyle.AllowNone`, `ToolBarStyle.NoDivider`, `StockCursor.SizeNesw`, `SystemMetric.DoubleClickMsec`, and `FontEncoding`'s Mac encodings, such as `MacCentralEuropean`. The paper sizes named by inches are named as System.Drawing.Printing names them, so `PaperKind.One0x11` is `Standard10x11`. A style a control borrows loses the other control's prefix, so `ComboBoxStyle.TeProcessEnter` is `ProcessEnter`, and `ChoiceStyle.CbSort` is `Sort`.
- British spellings that were left are American, as the rest are: `Cancelled` and `Cancelling` are `Canceled` and `Canceling`, as in `ColorPickerCtrl.DialogCanceled`, `Wizard.Canceling`, `IsEditCanceled`, and `PrinterError.Canceled`, `Image.ConvertToGreyscale` is `ConvertToGrayscale`, and `StyledTextCtrl.Colourise` is `Colorize`.
- Words that were spelled two ways are spelled one: `ScrollBar`, as the class is, so `Window.HasScrollbar` is `HasScrollBar`, and `ScrollbarVisibility` is `ScrollBarVisibility`. `FileName`, as .NET spells it, so `FileDialog.Filename` is `FileName`, and a `filename` parameter is `fileName`. `Ok`, as `StandardId.Ok` is, so `MessageDialog.OKLabel` is `OkLabel`. And `AutoScroll`.
- Abbreviations are spelled out: `GridSizer.Cols`, `HGap`, and `VGap` are `Columns`, `HorizontalGap`, and `VerticalGap`, `PrintData.NoCopies` is `Copies`, `Slider.TickFreq` is `TickFrequency`, `DC.MapMode` and `SizeMM` are `MappingMode` and `SizeInMillimeters`, `Printout.PageSizeMM` is `PageSizeInMillimeters`, `FromPhys` and `ToPhys` are `FromPhysical` and `ToPhysical`, and the calendar's colors are named as `HeaderForegroundColor` is, which was `HeaderColorFg`. `DataViewColumn.IsResizeable` is `IsResizable`.
- The enums `Reason` and `Origin` are `ActivationReason` and `HelpOrigin`.
- A color parameter that was named `column` is named `color`, as in `DC.FloodFill` and `ListCtrl.SetItemTextColor`, which matters only to a call that names it.
- Booleans are named as `IsChecked` is: `ActivateEvent.Active`, `CloseEvent.LoggingOff`, `Font.Underlined`, and `HyperlinkCtrl.Visited` take `Is`, `Printer.Abort` is `IsAborted`, `MenuItem.Checked` and `Enabled` are `IsChecked` and `IsEnabled`, and `UpdateUIEvent.Enabled` and `Shown` are `IsEnabled` and `IsShown`. `UpdateUIEvent.SetChecked`, `SetEnabled`, `SetShown`, and `SetText`, which say whether a handler set the state, are `IsCheckedSet`, `IsEnabledSet`, `IsShownSet`, and `IsTextSet`. `NavigationFlags.IsBackward` and `IsForward` are `Backward` and `Forward`.
- Events and members that read as commands are named for what they are: `FindReplaceDialog.Find`, `FindNext`, `Replace`, `ReplaceAll`, and `FindClose` are `FindRequested`, `FindNextRequested`, `ReplaceRequested`, `ReplaceAllRequested`, and `FindClosed`, `StyledTextCtrl.DoDrop` is `TextDropping`, and `DataViewCtrl.ItemStartEditing` is `ItemEditingStarting`. `TextValidator.IsValid`, which returns what is wrong with the text, is `GetError`.
- Parameters with Hungarian or abbreviated names are spelled out, in about 75 members, which matters only to a call that names them: `nPage` is `page`, `selImage` is `selectedImage`, `bmpDisabled` is `disabledBitmap`, `xdest` is `xDestination`, `minW` is `minWidth`, `hgap` is `horizontalGap`, `len` is `length`, and so on, and `FileDialog`'s `defaultDir` is `defaultDirectory`, as `FileCtrl`'s is.
- `ListCtrl`'s numbers are enums: an item's state is a `ListItemState`, so selecting one is `SetItemState(item, ListItemState.Selected, ListItemState.Selected)` rather than `SetItemState(item, 4, 4)`, `GetNextItem` takes a `ListNextItem` and a `ListItemState`, `Arrange` a `ListArrangement`, `TryGetItemRect` and `TryGetSubItemRect` a `ListRect`, and `FindItem` a `ListFindDirection`. `ListItem.State` and `Mask`, and `ListEvent.Mask`, are a `ListItemState` and a `ListItemMask`.
- More numbers are enums: `MouseEvent.Button` is a `MouseButton`, `ListEvent.KeyCode` and `TreeEvent.KeyCode` are a `KeyCode`, `ScrollEvent.Orientation` and `ScrollWinEvent.Orientation` are an `Orientation`, as is the orientation `Window`'s scroll bar members take, such as `GetScrollPosition` and `SetScrollBar`, and `Window.RegisterHotKey` takes `KeyModifiers`.
- And more: `Image.LoadFlags` and `DefaultLoadFlags` are an `ImageLoadFlags`, `KeyEvent.IsKeyInCategory` takes a `KeyCategory`, the message dialogs' `EffectiveIcon` is a `MessageIcon`, `FontData.RestrictSelection` is a `FontRestriction`, and `FileDialog.AddShortcut` takes a `FileDialogShortcut`.
- `CalendarEvent.WeekDay`, a `WeekDay`, is `DayOfWeek`, .NET's `DayOfWeek`, and the `WeekDay` enum is gone.
- Times are `TimeSpan`s: `TimerEvent.Interval`, `UpdateUIEvent.UpdateInterval`, where `Timeout.InfiniteTimeSpan` stops the updates, the timeouts `Window.ShowWithEffect` and `HideWithEffect` take, and `Simplebook.SetEffectTimeout` and `SetEffectsTimeouts`, which were milliseconds, and `NotificationMessage.Show`'s timeout, which was seconds. `Show()` leaves the timeout to the system, as `TimeoutAuto` did, and `Show(Timeout.InfiniteTimeSpan)` keeps the notification until it's closed, as `TimeoutNever` did. Both constants are gone.
- `Alignment` is `[Flags]`, since an alignment is one way across and one way down, and `Not`, `Mask`, and `Invalid` are gone. A column that defaulted to `Alignment.Not` defaults to `Alignment.Left`, the same value. `DC.DrawLabel` takes its alignment as an `Alignment`.
- `DC.UserScale` and `LogicalScale` are properties that give both scales as one value, as in `dc.UserScale = (2, 2)`, in place of `GetUserScale` and `GetLogicalScale`, which gave them through `out` parameters, and `SetUserScale` and `SetLogicalScale`.
- A property that gives a list gives an `IReadOnlyList<T>` rather than an array, as the hand-written ones did, such as `FileDialog.Paths`, `ListBox.Selections`, and `Window.Children`, 31 in all. Code that kept one in an array variable takes it as `IReadOnlyList<T>`, or with `var`, or copies it with `[.. dialog.Paths]`.
- A list's items and columns, and a text control's positions and lines, are `int`, as .NET's indexes are, where they were `long`: `ListCtrl`'s, `ListItem`'s, and `ListEvent`'s members, such as `InsertItem`, `GetItemText`, and the `OnGetItemText` a virtual list overrides, and `TextCtrl`'s, `ComboBox`'s, `SearchCtrl`'s, and `StyledTextCtrl`'s, such as `InsertionPoint`, `SetSelection`, `GetSelection`, `SelectionStart`, and `PositionToXY`. An item's data is still a `long`. `ListCtrl.SetItemCount` is gone, since `ItemCount` can be set.
- Events that were the same event under a second name are gone: `ToolBar.ToolClickedRange` and `ToolRightClickedRange`, `Window.HelpRange`, the nine `CommandScroll` events of each of `ScrollBar` and `Slider`, which the `Scroll` ones are, and `BitmapComboBox.Text`, which is `TextChanged`.
- `SplitterWindow.UnsplitEvent` is `WindowRemoved`, `NotificationMessage.Clicked` is `Click`, and `Window.SetCursor`, the event, is `CursorRequested`. `GenericDirCtrl`'s `FileActivated` and `SelectionChanged` give a `TreeEvent`, with the item.
- An event's members that filled it in are gone, since an application receives events and doesn't make them: 62 properties are read-only, such as `CommandEvent.String`, `MouseEvent.Position`, `ListEvent.Index`, and `StyledTextEvent.Position`, and 22 methods are gone, such as `KeyEvent.SetShiftDown` and `CloseEvent.SetCanVeto`. What a handler sets to answer an event stays: `SetCursorEvent.Cursor`, `SplitterEvent.SashPosition`, `TreeEvent.SetToolTip`, `UpdateUIEvent.Text` and `ThreeStateValue`, and the drag members of `DataViewEvent` and `StyledTextEvent`.
- More of wxWidgets' internals, and members only a class written in C++ overrides, are gone: `Window`'s `AddChild`, `RemoveChild`, `SetContainingSizer`, `PushEventHandler`, `PopEventHandler`, `RemoveEventHandler`, `SetNextHandler`, `SetPreviousHandler`, `OnInternalIdle`, `InformFirstDirection`, `CacheBestSize`, and the three `AcceptsFocus` members; the sizers' `CalcMin`, `RepositionChildren`, and `InformFirstDirection`; `SplitterWindow`'s `OnSashPositionChange`, `OnDoubleClickSash`, and `OnUnsplit`; `ScrolledWindow.PrepareDC`; `Image`'s and `Bitmap`'s `CleanUpHandlers` and `InitStandardHandlers`; `Dialog`'s layout adaptation members and `DialogLayoutAdaptationMode`; `DC`'s `StartDoc`, `EndDoc`, `StartPage`, and `EndPage`; `MenuBar.Attach` and `Detach`; `Event`'s `EventUserData`, `EventCategory`, and `IsCommandEvent`, and the `EventCategory` enum; and `StyledTextCtrl`'s `DoDragEnter`, `DoDragOver`, `DoDragLeave`, and `DoDropText`.
- Members that only repeated another are gone:
  - `KeyEvent`'s and `MouseEvent`'s `AltDown`, `ControlDown`, `MetaDown`, `ShiftDown`, and `CmdDown`, which `Modifiers` gives, as in `e.Modifiers.HasFlag(KeyModifiers.Shift)`. `RawControlDown` stays.
  - `GetSelection(out int from, out int to)` of `TextCtrl`, `ComboBox`, `SearchCtrl`, and `StyledTextCtrl`, which `SelectionStart` and `SelectionLength` give, or the styled text control's `SelectionEnd`.
  - `Window`'s static `FromDip`, `ToDip`, `FromPhysical`, and `ToPhysical`, which took the window. The window's own do the same.
  - Setters beside a property: `Dialog.SetIcon`, `StaticText.SetLabel`, `TopLevelWindow.SetMinSize` and `SetMaxSize`, `InfoBar.SetFont`, and `ListCtrl.SetBackgroundColor`.
  - `Brush.SetColor` and `Pen.SetColor`, which took three bytes, and `ColorPickerCtrl.SetColor`, which took a name. Set `Color`.
- `StyledTextCtrl`'s Scintilla names for what it has under `TextCtrl`'s names are gone: `Modify` (use `IsModified`), `GetLine` (`GetLineText`, which leaves out the line's end), `LineLength` (`GetLineLength`), `LineCount` (`NumberOfLines`), `GetTextRange` (`GetRange`), and `ReadOnly` (`IsEditable`, which is its opposite). Its `Clear`, which deleted the selection where `TextCtrl.Clear` clears everything, is `DeleteSelection`. `ClearAll` clears everything.
- Enum members that weren't values to use are gone:
  - Bounds and values for none: `Max` of `FontEncoding`, `FontFamily`, `FontStyle`, `FontWeight`, `HitTestResult`, `MouseButton`, `ShowEffect`, `TreeItemIcon`, and `WindowVariant`; `FontEncoding`'s `Iso8859Max`, `Cp12Max`, and `MacMax`; `HitTestResult`'s `ScrollBarFirst` and `ScrollBarLast`; `Invalid` of `BitmapType`, `BrushStyle`, `FontWeight`, `PenCap`, `PenJoin`, and `PenStyle`; and `Border.Mask`.
  - `BitmapType.Tif` and `TifResource`, which are `Tiff` and `TiffResource`.
  - Styles that are 0, which `HasFlag` found in every value. Use `None`, or leave the style out: `ListBoxStyle.NeededSb`, `TextCtrlStyle.Left` and `BestWrap`, `SearchCtrlStyle.Left`, `SpinCtrlStyle.AlignLeft`, `SpinCtrlDoubleStyle.AlignLeft`, `StaticTextStyle.AlignLeft`, `TreeCtrlStyle.Single` and `NoButtons`, `TreeListCtrlStyle.Single` and `Default`, `DataViewCtrlStyle.Single`, `SplitterWindowStyle.NoBorder` and `ThinSash`, `MessageDialogStyle.OkDefault` and `YesDefault`, `WindowStyle.BorderDefault`, `NoFullRepaintOnResize`, and `TransparentWindow`, and `Default` of `ChoicebookStyle`, `ListbookStyle`, `ColorPickerCtrlStyle`, and `DatePickerCtrlStyle`.
- `DataViewColumnFlags`, `FindReplaceFlags`, `FindReplaceDialogStyle`, `KeyCategory`, and `WebViewBrowsingDataTypes` have `None`.
- `Font`'s members that return a changed copy are named one way: `WithBold`, `WithItalic`, `WithLargerSize`, `WithSmallerSize`, and `WithScaledSize`, which were `Bold`, `Italic`, `Larger`, `Smaller`, and `Scaled`, beside `WithUnderline` and `WithStrikethrough`. `MakeBold` and the others that changed the font itself, and `Scale`, are gone. Set `Weight`, `Style`, `IsUnderlined`, or `PointSize` to change a font.
- `MouseEvent`'s queries are properties: `IsDragging`, `IsEntering`, `IsLeaving`, `IsMoving`, and `IsMagnify`; for each of the left, middle, right, and two auxiliary buttons, `IsLeftDown`, `IsLeftUp`, and `IsLeftDoubleClick`, which were `LeftDown()`, `LeftUp()`, and `LeftDClick()`; and `IsLeftButtonPressed`, which was `LeftIsDown()`, for a button that is held.
- A getter with a setter under another name is one property: `DC.DeviceOrigin` and `LogicalOrigin`, which take a `Point` (`SetDeviceOrigin` and `SetLogicalOrigin` are gone), `CollapsiblePane.IsCollapsed` (`Collapse` is gone, and `Expand` stays), `ListCtrl.HasCheckBoxes` (`EnableCheckBoxes`), `SearchCtrl.IsSearchButtonVisible` and `IsCancelButtonVisible` (`ShowSearchButton` and `ShowCancelButton`), and `MemoryDC.SelectedBitmap` (`SelectObject`).
- `TextCtrl.PositionToXY` and `StyledTextCtrl`'s are `TryGetColumnAndLine(position, out column, out line)`, and `XYToPosition` is `PositionFromColumnAndLine(column, line)`.
- `Image.Rescale` and `Resize`, which change the image, return nothing, so they aren't taken for `Scale` and `Resized`, which return a copy.
- `GridSizer` and `FlexGridSizer` have one constructor, which takes the columns and a gap, as in `new FlexGridSizer(2, new Size(5, 5))`, in place of four whose first number was the rows or the columns by how many followed. The grid has as many rows as its items need. The gap's width is the space across and its height the space down.
- `Window.FindWindow` and `FindWindowById` take the id as an `int`, as every other member does, where they took a `long`.
- More properties in place of a getter and a setter that didn't pair:
  - `Window.ToolTipText` can be set, and setting it empty takes the tooltip away. `SetToolTip` and `UnsetToolTip` are gone.
  - `SplitterWindow.SashPosition` can be set. `SetSashPosition` is gone.
  - `BookCtrlBase.Selection`, which `Notebook` and the other books have, can be set, and setting it raises no events, as setting any control's selection does. `SetSelection`, which raised the page events, and `ChangeSelection` are gone.
  - `CalendarCtrl`'s six colors, such as `HeaderForegroundColor`, can be set one at a time. `SetHeaderColors`, `SetHighlightColors`, and `SetHolidayColors` are gone. A platform's own calendar, such as the one on Windows, ignores them, as it did.
  - `Image.MaskColor` is the mask's color, or null without a mask, in place of `MaskRed`, `MaskGreen`, `MaskBlue`, `SetMaskColor`, and `SetMask`.
- A method that took x and y, or a width and a height, beside an overload that takes a `Point`, a `Size`, or a `Rect`, is gone, 34 in all, so `dc.DrawText(text, 10, 10)` is `dc.DrawText(text, new Point(10, 10))`, and `dc.DrawLine(0, 0, 50, 50)` is `dc.DrawLine(new Point(0, 0), new Point(50, 50))`. They are `DC`'s drawing members, `DeviceToLogical`, `LogicalToDevice`, `FloodFill`, and `SetClippingRegion`; `Image.Scale` and `Rescale`; `Bitmap`'s and `Image`'s `Create` members; `ScrolledWindow.Scroll`; and `Window`'s `HitTest`, `IsExposed`, `PopupMenu`, `Move`, `SetSize`, `SetClientSize`, and `SetVirtualSize`. Constructors keep both forms, so `new Bitmap(20, 20)` still works.
- `Dialog.ShowWindowModal` is `ShowWindowModalAsync`, whose task gives what the dialog returned when it closes, as in `int result = await dialog.ShowWindowModalAsync();`. The `WindowModalClosed` event stays.
- `ListCtrl.GetItem(item, column)` and `GetColumn(column)` return a `ListItem` with the text, image, data, state, alignment, and width, or null when the list has no such item or column, in place of filling one the caller made and set a mask on. Dispose the item when done with it.
- `Image` takes a color as a `Color` and a pixel as a `Point`, where it took three bytes and x and y: `GetRgb(pixel)`, which gives a `Color` in place of `GetRed`, `GetGreen`, and `GetBlue`; `SetRgb(pixel, color)` and `SetRgb(rect, color)`; `GetAlpha(pixel)`, `SetAlpha(pixel, alpha)`, and `IsTransparent(pixel)`; `Replace(from, to)`; `ConvertToMono(color)`; `ConvertAlphaToMask(color)`; `SetMaskFromImage(mask, color)`; and `Resize` and `Resized`, whose border is a `Color?` in place of three numbers that were -1 for none.
- `Bitmap.FromDipSize(size, scale)` and `Bitmap.FromLogicalSize(size, scale)` make a bitmap in one step, and throw when they can't, in place of `CreateWithDipSize` and `CreateWithLogicalSize` on an empty bitmap. `Bitmap.Create`, `Bitmap.CreateScaled`, and `Image.Create` are gone, since a constructor takes the size.
- A data view model's members that tell its controls what changed begin with `Notify`, so they don't read as events: `NotifyItemChanged`, `NotifyValueChanged`, `NotifyItemAdded`, `NotifyItemDeleted`, and `NotifyCleared`, and a virtual list model's `NotifyRowAppended`, `NotifyRowPrepended`, `NotifyRowInserted`, `NotifyRowDeleted`, `NotifyRowChanged`, and `NotifyRowValueChanged`. `Reset` and `Resort` keep their names. `Cleared` and `ItemDeleted` were virtual, and none is now.
- `LiveRegion` derives from `Control` rather than `StaticText`, whose label and wrapping it had no use for.
- In F#, `grow`, `fill`, `center`, `alignRight`, `border`, and `noBorder` take a window or a sizer as well as an item, so `list |> grow` and `row { ... } |> fill` work without `item` and `section`, which still do. This needs no change to code. The functions are inline now. One passed as a value takes its type from what it's given, as in `buttons |> List.map grow`, and only one bound to a name alone, as in `let change = grow`, needs its type written, as in `let change: Window -> LayoutItem = grow`.
- `Dialog.CreateStdDialogButtonSizer(DialogButtons.Ok | DialogButtons.Cancel)` makes a dialog's standard buttons, in the platform's order, as a sizer to add to the dialog's. This is new.
- `DataViewTreeModel<T>` can be made with an `IEqualityComparer<T>`, so an item is known by a key, such as an id, rather than by the object it is. An object that changes by being copied, as an F# record does, then stays the item it was, and `NotifyItemChanged` with the copy keeps the copy. This is new.
- A `Paint` handler paints on the event's `DC`, as in `panel.Paint += (_, e) => e.DC.DrawLine(...)`, where it made a `PaintDC` and had to dispose it. The event disposes it when the handlers return, and `PaintDC` has no public constructor. A handler that paints nothing and doesn't call `Skip` still leaves the window painted, where Windows used to send the event again without end.
- A window is given its drop target and its accessible object by assignment, where their constructors took the window: `DropTarget target = new(DataFormat.Text); list.DropTarget = target;` and `board.Accessible = new BoardAccessible();`. A class derived from `Accessible` no longer passes a window to its base. Setting either to null takes it away, which replaces `DropTarget.Remove`, and gives the window its standard accessible object back. `DropTarget.Window` is null, and `Accessible.Window` throws, while no window has it.
- `TreeCtrl.OnCompareItems` is a protected member to override, which `SortChildren` asks for the order of two items, where it was a public member that only compared two items' text. A class derived from `TreeCtrl` sorts its own way by overriding it.
- The last members that took a place or a size as two numbers take one value. `DC.Blit` takes Points and a Size, and `StretchBlit` two Rects. `DC.CalcBoundingBox`, `DC.DrawSpline`, `Image.Paste`, `Printout.SetLogicalOrigin` and `OffsetLogicalOrigin`, `ToolBar.FindToolForPosition`, `Window.WarpPointer`, and the styled text control's `CharPositionFromPoint`, `CharPositionFromPointClose`, and `PositionFromPointClose` take Points. Those that repeated a member that takes one value are gone: `DC.DrawArc` with six numbers, `DeviceToLogicalRel` and `LogicalToDeviceRel` with two, `GetSizeFromTextSize` with two, `AnyButton.SetBitmapMargins`, for the `BitmapMargins` property, and `ToolBar.SetMargins`, for `Margins`.
- The styled text control's autocompletion settings are properties, where Scintilla's names gave each a method to get it and one to set it: `AutoCompAutoHide`, `AutoCompCancelAtStart`, `AutoCompChooseSingle`, `AutoCompDropRestOfWord`, `AutoCompIgnoreCase`, `AutoCompCaseInsensitiveBehavior`, `AutoCompMaxHeight`, `AutoCompMaxWidth`, `AutoCompMulti`, `AutoCompOrder`, `AutoCompSeparator`, and `AutoCompTypeSeparator`, with `AutoCompCurrent` and `AutoCompCurrentText` to read. `CallTipPosAtStart` is one too, and `AutoCompActive()`, `CallTipActive()`, and `SelectionIsRectangle()` are the properties `IsAutoCompActive`, `IsCallTipActive`, and `IsSelectionRectangle`.
- `PrintDialogData`'s `EnablePrintToFile`, `EnableSelection`, `EnableCurrentPage`, `EnablePageNumbers`, and `EnableHelp` are properties, as `PageSetupDialogData`'s are, where they were methods that only set.
- A `TreeItemId` or a `TreeListItem` can't be made from a number, and doesn't give its number, since it is a pointer the control follows, and one made up could crash it. Only the controls give them out. A `DataViewItem` still can, since a model names its own items.
- `StatusBar.SetStatusStyles` takes `StatusBarFieldStyle` values, as `GetStatusStyle` returns, where it took numbers.
- `StyledTextEvent.Modifiers` is `KeyModifiers`, converted from Scintilla's numbers, which differ: its Shift was 1 and its Alt 4, where `KeyModifiers.Shift` is 4 and `Alt` is 1. Code that compared the number with Scintilla's values compares with `KeyModifiers` members.
- `IsDestroyed` is `IsDisposed`, on windows and other event handlers, sizers, data view columns, and toolbar tools, so everything says whether it is gone with one name, the one of the `ObjectDisposedException` its members then throw.
- `Menu` is `IDisposable`. Disposing a menu that is on no menu bar and in no menu frees it, such as one made for `PopupMenu`, which was never freed. A menu on a menu bar or in a menu is its owner's, and disposing it does nothing.
- A `MenuItem` wraps the native item, where it was a menu and an id, so one separator isn't another, and it has `Help`, `IsSeparator`, and `SubMenu`. Its members throw `ObjectDisposedException` once its menu is destroyed. This needs no change to code.
- `Choice`, `ComboBox`, `ListBox`, and `CheckListBox` have one constructor each, whose list of items can be left out, where the constructor without a list couldn't take a style. `new ListBox(parent, style: ListBoxStyle.Multiple)` works now. A call that gave an id by position, as in `new ListBox(parent, id)`, names it: `new ListBox(parent, id: id)`.
- The object kept with an item of a `Choice`, `ComboBox`, or `ListBox` has one name, item data, as a tree's does: `GetClientObject` and `SetClientObject` are `GetItemData` and `SetItemData`, the `clientData` parameter of `Append` and `Insert` is `data`, and `CommandEvent.ClientObject` is `ItemData`. `HasClientData`, `HasClientObjectData`, and `HasClientUntypedData` are gone, since which kind of data a control keeps is WxKit's affair.
- `Choice`, `ComboBox`, and `ListBox` implement `IItemContainer`, which has the members they share, so code that fills or reads a list can take any of them. This is new.
- A window's styles are its `Style` property, of its class's own style enum, as in `list.Style.HasFlag(ListBoxStyle.Multiple)` and `panel.Style |= WindowStyle.WantsChars`. It replaces `Window.WindowStyle`, `WindowStyleFlag`, `SetWindowStyle`, `HasFlag`, and `ToggleWindowStyle`, which took a `WindowStyle`, a long, and an int between them, and `ListCtrl.SetWindowStyleFlag`.
- Each control's style enum has the styles every window takes, such as `ListBoxStyle.BorderNone` and `TextCtrlStyle.WantsChars`, so they need no cast from `WindowStyle`. This is new.
- `TextEntryDialog` and `PasswordEntryDialog` take a `TextEntryDialogStyle` rather than a `DialogStyle`, whose members weren't the ones they take. It has `Ok`, `Cancel`, `Center`, `MultiLine`, `Password`, and `Default`. `SingleChoiceDialogStyle` and `MultiChoiceDialogStyle` gain `Default`, `Caption`, `SystemMenu`, `CloseBox`, and `ResizeBorder`, so their defaults have a name.
- `KeyModifiers` has `RawControl`, the Control key of a Mac, where `Control` is the Command key. Only macOS reports it. `KeyEvent.RawControlDown()` and `MouseEvent.RawControlDown()` are gone: test `e.Modifiers.HasFlag(KeyModifiers.RawControl)` on macOS, and `KeyModifiers.Control` elsewhere. A styled text event's `Modifiers` gives it under that name too.
- `StyledTextCtrl.Text`, `TextLength`, and `CurrentPos` are gone, which repeated `Value`, `LastPosition`, and `InsertionPoint`, the names every text control has.
- An image or bitmap is loaded with a static method that returns null when it can't be: `Image.FromFile`, `Image.FromStream`, and `Bitmap.FromFile`. They replace the constructors that took a file's name, which gave an object that wasn't usable when loading failed, and `Bitmap()` and `Image()` with `LoadFile`. Write `Image.FromFile(path)` for `new Image(path)`, and `Image.FromStream(stream)` for `new Image()` and `LoadFile(stream)`, and check the result for null rather than `IsOk`.
- `Window.EventHandler` is gone. It hid `System.EventHandler` in every class derived from a window, so `EventHandler<T>` there needed `System.` written, and setting it was wxWidgets' own plumbing, as `PushEventHandler` was.
- `TextValidatorStyle` is `[Flags]`, which its values always were, and `TextValidator.HasFlag` is gone: write `validator.Style.HasFlag(TextValidatorStyle.Digits)`.
- The number kept with a list's item is a `long` to set as it is to read: `ListItem.Data` is a property that can be set, in place of `SetData(int)`, and `ListCtrl.SetItemData` takes a `long`.
- Two parameters that were C# keywords are renamed, which matters only to a call that names them: `Font.SetSymbolicSizeRelativeTo`'s `base` is `baseSize`, and `InfoBar.ShowCheckBox`'s `checked` is `isChecked`.
- In F#, `trn` and `trpn` take a count of any integer type, so `trn "{0} file" "{0} files" files.Length` compiles. They took an `int64`, which F# doesn't widen an `int` to.
- More members that only wxWidgets calls are gone: `Window.SetFocusFromKbd`, `GetMinSizeFromKnownDirection`, `AdjustForLayoutDirection`, `UseBackgroundColor`, `UseForegroundColor`, and `GetBorder(long)`, `TopLevelWindow.ShouldPreventAppExit` and `TmpDefaultItem`, `Image.Destroy`, which `Dispose` does, and `Bitmap.RemoveHandler` and `Image.RemoveHandler`, which took a name nothing gives.

## Added

- An F# project that publishes with Native AOT compiles with `--reflectionfree`, so its records and unions don't give trim warnings. Set `WxKitReflectionFree` to `false` to compile without it.
- The samples are in `samples/csharp` and `samples/fsharp`, each in both languages, and there are four new ones: Library lists books in a data view with a model of its own, filtered as a search is typed, Checksums hashes files on another thread with a progress dialog that can cancel, Scrapbook uses the clipboard and drag and drop, and ProjectWizard is a wizard that skips a page that doesn't apply.
- The translation extractor marks a string passed first to `String.Format`, as F# formats a translation, as formatted, so that `msgfmt` checks its translations' placeholders.
- `StaticBoxSizer.StaticBox` isn't nullable, since the sizer always has its box.
- `SearchCtrl.TextChanged` is raised as the search control is typed in, for filtering as the user types. Its documentation lists only its search events, though every port sends it.

## Accessibility

- An `Accessible` that answers `AccessibleElement.Self` from `HitTest` or `Navigate` gives screen readers the window, rather than telling them nothing is there, which broke exploring the window with the mouse or by touch.
- `SetAccessibleParts`, `SetAccessibleRows`, and `SetAccessibleCurrentRow` work on Linux and macOS for a window with an `Accessible` of its own, which only Windows asks. They threw.
- A control after a `LiveRegion` is named by the label before the live region, on Linux and macOS, and a window with parts or rows is named the same way on Windows. The live region, whose text is announced rather than shown, was taken as the label. On Windows, Windows itself names a standard control by the text just before it, so put a live region somewhere other than between a label and its control.

## Members that couldn't work

- `ScrollBar.SetScrollBar(position, thumbSize, range, pageSize)` sets the scroll bar. It was missing, since `Window.SetScrollBar`, which took its orientation as a number, had the same parameters, so a call meant for the scroll bar set the window's.
- `ProgressDialog` has the members that show progress: `Update` and `Pulse`, which take a new message too, `Value`, `Range`, `Message`, and `Resume`, and `IsCanceled` and `IsSkipped`, which say whether the user canceled or skipped. It could only be shown.
- `Pen.Color` can be set, as `Brush.Color` can. wxWidgets' documentation gave its setter a parameter WxKit couldn't take.
- `ListCtrl.GetItemData` reads the data `SetItemData` gives an item, `FindItem` finds an item by it, and `ListItem.Data` and `ListEvent.Data` give it.
- `DataViewTreeCtrl` has `SetImages`, which gives the images its items' icons are indexes into. It had no images, so the icons were ignored.
- `Dialog.WindowModalClosed` says when a dialog shown with `ShowWindowModal` closes, and what it returned, since on macOS `ShowWindowModal` doesn't wait for it.
- Setters that wxWidgets clears with null take null: `Frame.StatusBar` and `ToolBar`, `TopLevelWindow.DefaultItem`, `SearchCtrl.Menu`, and `WizardPageSimple.SetNext` and `SetPrevious`. They threw.
- `WebViewFindFlags` is `[Flags]`, so its flags combine.

## Samples

- The Editor sample's printout kept the editor's font, which the editor disposed as soon as it made the printout, so previewing or printing ended the editor with an error. Its smoke test closed the preview before wxWidgets, which lays the pages out when it first draws one, used the printout, so CI didn't see it. The printout makes its own font now, and the smoke test waits for a page to be drawn.

## Leaks

- Replacing `Frame.MenuBar` destroys the menu bar it replaces, as the frame would have with itself. wxWidgets only detached it, so it stayed, with its menus and handlers.
- A `Printout` the application lets go of without disposing it is freed, as other native objects are. One given to a preview stays until the preview deletes it.
- Deleting an item from a `DataViewTreeModel<T>` forgets the items under it too, not only the item itself.

## Safety

- `Image.FromStream`, which was `LoadFile(Stream)`, loads nothing from a memory stream positioned past its end. It read past the stream's buffer.
- Freeing an object from the garbage collector's thread while the application exits can't reach the application as wxWidgets deletes it.
- Looking up a translation on another thread while the GUI thread adds a catalog, or sets the language, waits for it, rather than reading a catalog half added.
- `SingleInstance.MessageReceived` raises messages that arrived before `Application.Run`, when a handler was added before it. They waited until another copy sent one.

WxKit is heavily vibe coded. If AI-written code is a dealbreaker for you, this is not the project for you.
